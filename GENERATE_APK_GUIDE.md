# Generate APK Guide

How to build an installable Android **APK** for this Expo app **locally** on a Linux
machine. Written to be followed step-by-step by a human or an AI coding agent.

> TL;DR: once the toolchain is set up, run
> `eas build --local --profile preview --platform android` from the repo root.
> The signed APK is written to `build-<timestamp>.apk` in the project root.

---

## 1. Project facts (do not guess — these are fixed)

| Thing | Value |
| --- | --- |
| Framework | Expo SDK **57**, React Native **0.86.3**, React **19.2** |
| Workflow | **Managed** (no committed `android/` folder; it is generated by prebuild) |
| Entry | `expo-router/entry` (see `package.json` → `main`) |
| Android package | `com.yogesh.expensemanager` |
| Required JDK | **17** (Gradle 9.x refuses JDK 11) |
| Required Android `compileSdk` / `targetSdk` | **36** (set in `app.json` → `expo-build-properties`) |
| `minSdk` | 26 |
| Build tooling | `eas-cli` local builds (`eas build --local`) or raw Gradle |
| APK output | project root, `build-<timestamp>.apk` (universal, all ABIs, signed) |
| Platform limit | iOS cannot be built on Linux — Android only here |

The APK is signed with the **remote Expo keystore** (managed credentials on the
Expo server), so `eas login` is required the first time.

## 2. One-time machine setup

These are environment/SDK installs. They only need to be done once per machine.
All paths stay in the shell profile and env vars — **never hardcode machine paths
into the repo** (keeps the build portable across machines).

### 2a. Java 17

RN 0.86 + Gradle 9 require JDK 17. A shell *alias* is NOT enough — Gradle spawns
a daemon that reads `JAVA_HOME`/`PATH`, not interactive aliases.

```bash
# Install if missing (Debian/Ubuntu):
sudo apt update && sudo apt install -y openjdk-17-jdk
# Typical path: /usr/lib/jvm/java-17-openjdk-amd64
```

### 2b. Android SDK (command-line tools only — no Android Studio needed)

```bash
SDK="$HOME/Android/Sdk"
mkdir -p "$SDK/cmdline-tools"
cd "$SDK/cmdline-tools"
curl -sSLo cmdtools.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip -q cmdtools.zip && mv cmdline-tools latest && rm cmdtools.zip
```

### 2c. Persist environment in `~/.bashrc`

Append once (idempotent — check for `ANDROID_HOME=` before adding):

```bash
# --- Android/React Native build toolchain ---
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export ANDROID_HOME=$HOME/Android/Sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/27.1.12297006
export PATH=$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH
```

Then `source ~/.bashrc` (or open a new terminal).

### 2d. Install required SDK packages

```bash
yes | sdkmanager --licenses
sdkmanager \
  "platform-tools" \
  "platforms;android-35" "platforms;android-36" \
  "build-tools;35.0.0" "build-tools;36.0.0" \
  "ndk;27.1.12297006" "cmake;3.22.1"
```

`android-36` + `build-tools;36.0.0` are **required** because Expo 57 / RN 0.86
AndroidX dependencies (`androidx.activity`, `androidx.core`, …) must compile
against API 36.

### 2e. Verify

```bash
java -version                 # must report 17.x
adb --version                 # Android Debug Bridge present
ls "$ANDROID_HOME/ndk"        # 27.1.12297006
ls "$ANDROID_HOME/platforms"  # android-35  android-36
```

## 3. Build the APK

> This repo's `node` is at `~/.nvm/versions/node/v20.20.2`. If `npm`/`npx` fail
> with an `ENOENT` about a bad prefix, prefix commands with
> `npm_config_prefix=/home/im_ykp/.nvm/versions/node/v20.20.2`.

### Option A — EAS local build (recommended; produces a signed APK)

Uses the `preview` profile from `eas.json` (which sets `android.buildType: apk`).
The `production` profile builds an `.aab`, **not** an APK — do not use it for a
sideloadable file.

```bash
cd <repo-root>
eas login                 # first time only
eas build --local --profile preview --platform android
```

- Runtime: ~25 min on a cold cache (downloads Gradle + deps, compiles native code
  for all ABIs). Subsequent builds are much faster (warm Gradle cache).
- Output: `build-<timestamp>.apk` in the project root (universal, ~110 MB, signed).

### Option B — Raw Gradle (no EAS account; unsigned/debug)

```bash
cd <repo-root>
npx expo prebuild --platform android --clean   # generates ./android
cd android
./gradlew assembleRelease   # -> app/build/outputs/apk/release/app-release.apk (unsigned)
# or, for an immediately-installable self-signed build:
./gradlew assembleDebug     # -> app/build/outputs/apk/debug/app-debug.apk
```

A `release` APK built this way is **unsigned** and will not install until signed;
use `assembleDebug` for quick on-device testing, or Option A for a signed release.

---

## 4. Install on a device

```bash
# USB debugging enabled on the phone:
adb install build-<timestamp>.apk
```

Or copy the `.apk` to the phone and tap it (enable "install from unknown sources").

## 5. Troubleshooting (observed failures and fixes)

| Symptom in logs | Cause | Fix |
| --- | --- | --- |
| `Gradle requires JVM 17 or later ... currently configured to use JVM 11` | `JAVA_HOME`/`PATH` point at JDK 11 (a `java17` *alias* does not propagate to the Gradle daemon) | Set real `JAVA_HOME` to JDK 17 (§2c), re-run |
| `SDK location not found` / missing `adb` | Android SDK not installed or `ANDROID_HOME` unset | Do §2b–§2d |
| `checkReleaseAarMetadata FAILED ... requires ... compile against version 36` | `compileSdk` < 36 | `app.json` → `expo-build-properties` → `compileSdkVersion`/`targetSdkVersion` = **36**, install `platforms;android-36` |
| `ANDROID_NDK_HOME ... not specified` (then continues) | NDK path not exported | Non-fatal, but export `ANDROID_NDK_HOME` (§2c) to silence and speed up |
| Output is `.aab`, not `.apk` | Used the `production` profile | Use `--profile preview` (or `development`) |
| `Daemon will be stopped ... out of JVM Metaspace` | Gradle memory warning | Non-fatal. To silence, add `org.gradle.jvmargs=-Xmx4g -XX:MaxMetaspaceSize=1g` to `android/gradle.properties` |
| `expo doctor` schema warnings (`newArchEnabled`, `splash`, `edgeToEdgeEnabled`) | Stale config schema / deprecated keys | Non-fatal for the build; safe to clean up later |

## 6. Notes for AI agents

- **Do not commit** the `.apk` (it is ~110 MB). Ensure `build-*.apk` is
  gitignored before any `git add -A`.
- The `app.json` `compileSdk`/`targetSdk` = 36 change **is** source and should be
  committed — it also fixes EAS cloud builds.
- Builds are long; run them in the background and poll the log rather than
  blocking a single foreground call. Success is the line
  `Build successful` / `You can find the build artifacts in <path>.apk`.
- `node` here is v20; `eas-cli` warns it will require v22 "in a future release" —
  currently non-blocking.
- Re-running `eas build --local` reruns `prebuild` in a temp dir, so it does
  **not** dirty the repo's working tree (no stray `android/` is left behind).
